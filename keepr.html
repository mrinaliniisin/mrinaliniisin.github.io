Keepr

A small local app for the moment your Downloads folder becomes unmanageable — swipe through everything once, keep what matters, and let the rest go.

If you pull media in bulk — gallery-dl, a camera roll export, years of a group chat's shared folder — you end up with thousands of files and no good way to go through them. Keepr turns that pile into a deck: one photo or video at a time, full-screen, decide and move on. It's a single Python file with no dependencies, runs entirely on your own machine, and nothing leaves your computer.

This walkthrough covers getting it running and using every part of it, illustrated with what each screen actually looks like.

What you'll need

  • A Mac, and Python 3 (Keepr uses osascript for a few features, so those are macOS-only)
  • A folder of photos and/or videos you want to sort through
  • (Optional) Tailscale installed, if you want to review from your phone too

1. Start the server

Keepr is one script. From the folder it lives in:

python3 keepr_server.py

It prints the address to open:

Serving on http://127.0.0.1:8743  (folder: not set yet)

Open that in a browser. If Tailscale is running on the same machine, it also binds to your Tailscale IP on the same port automatically — so the exact same app, with the exact same review progress, is reachable from your phone or another computer on your tailnet.

2. Point it at a folder

the first-run wizard

The first time you open Keepr — or any time it can't find the folder it last used — it shows a short setup screen instead of guessing:

Clicking Choose a folder… opens the normal macOS folder picker (the same dialog you'd get from Finder), so you browse to the right place instead of typing an absolute path from memory. If you're reviewing from a phone over Tailscale, that dialog would pop up on the Mac's screen where you can't see it — so there's always a plain text field as a fallback, plus a list of folders you've used recently once you have any.

Once a folder is chosen, Keepr remembers it (in keepr_config.json) and reopens straight into it next time — the wizard only shows up when nothing's set.

3. Swipe

the review deck

Now the actual work: one file, front and center. Keep it or delete it, then the next one appears automatically.

Three equivalent ways to decide, so you can use whichever suits how you're holding the device:

  • Drag the card left (delete) or right (keep) — it flies off and the next one takes its place
  • Click × Delete / ♥ Keep
  • Press ← to delete, → to keep, U to undo the last decision

Videos get their own controls instead of a swipe gesture, since dragging a video would fight with scrubbing it: Space plays or pauses, M toggles mute (every video starts muted so a deck of clips doesn't blast sound), and J / K jump back or forward 5 seconds.

The comment box under the card writes straight into the file's Finder Comments field — so a note like "blurry, skip" or "use for the album" shows up if you look at the file in Finder later, with no separate database to keep in sync.

Deleting is not erasing. A "deleted" file is moved into a _deleted/ folder right inside the folder you're reviewing. Nothing is permanently removed, and U puts it straight back if you change your mind.

4. Check your buckets

Deleted / Kept / Remaining

The counts in the header aren't just a tally — click any of them (or the Keepr logo, for what's left) to see the actual files in that bucket, as a scrolling grid:

It's a good way to double-check yourself before walking away — scan the Deleted bucket for anything you swiped too fast, or the Kept bucket to see the set you're about to end up with. The Remaining bucket (everything not yet decided) has its own Start Swiping! button, so you can browse the queue without committing to reviewing in order.

5. Switch folders or reset

the header path & Settings

The active folder's full path sits right in the header. Click it, and the same native folder picker from setup opens immediately — no detour through a menu:

For anything less immediate, the gear icon opens Settings:

Reset progress clears the kept/deleted history Keepr is tracking for that folder, so everything shows up for review again. It does not restore files already sitting in _deleted/, and it doesn't touch any Finder comments you've written — it only forgets what's been decided.

Review state lives in a small .review_state.json file inside the folder itself, not in the browser. Move or rename the folder and its progress moves with it; open the same folder from a different device on your tailnet and you'll see exactly where you left off.

6. Finish

All reviewed!

Once every file has a decision, the deck is replaced with a summary:

From here it's an ordinary folder again — 108 kept files sitting where they always were, and a _deleted/ subfolder holding the rest in case you want a second look before actually clearing it out yourself.

Every shortcut, in one place

Key Does
← Delete the current file
→ Keep the current file
U / Backspace Undo the last decision
Space Play / pause (video only)
M Mute / unmute (video only)
J / K Seek 5s back / forward (video only)
⌘C Copy the current file to the clipboard
Esc Close Settings or a gallery view

That's the whole app. There's no account, no sync, no cloud step in between — it's a Python script talking to a single HTML page on your own network.
